# Milestone 4: Disk map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Disk map" route in Discky.app: a squarified treemap of the current index with breadcrumbs, three colourings (Category / Age / Files), On disk / Claimed weights, draw depth 1–4, hover tooltip, double-click descent, and the existing right-hand inspector for any tile (path details, Show in Finder, Move to Trash, "Show in <category>" for known findings) — plus three M3 follow-ups that touch the same inspector/planner code.

**Architecture:** The index already carries per-node subtree aggregates (`agg_allocated`, `agg_logical`, `agg_private`, `agg_files`, `max_mtime`), so the map is a pure read of `Arc<Index>`: a GPUI-free `MapModel` (navigation state, weights, colouring, nested squarified layout, hit-testing, tooltip rows) feeds one `canvas` that paints quads and labels; mouse events live on the canvas's parent `div` and hit-test against the cached tile list. Core gains two small APIs: a node→finding map (`query::NodeFindings`, nearest-ancestor lookup) used for the Category colouring and the inspector link, and `plan_paths` (Trash steps for arbitrary index paths with refusal rules), so the map's "Move to Trash" runs through the same planner, executor, dialog and history as every other removal. The inspector gets a second subject (a path) next to its existing `Finding` subject.

**Tech Stack:** Rust 1.99, gpui-kit `=0.9.0` (gpui-pre 0.3.11: `canvas`, `paint_quad`, `BorderStyle::Dashed`, `shape_line`, `Breadcrumb`, `TabBar::segmented`), existing crates only (no new dependencies).

**Spec:** `docs/superpowers/specs/2026-11-02-discky-design.md` §5 (honest bytes, sparse, dataless, hard links), §10 (disk map), §11 (inspector, sidebar group "Disk"), §14 (60 fps hover at 5 000 tiles), §17.1/3/5. Mockup: `.superpowers/brainstorm/47903-1793645957/content/03-treemap.html` (tile border, white hover outline, 300 px tooltip with action chips, legend row). ## Global Constraints

- Sizes come from the index only: tile weight = `agg_allocated` / `allocated` ("On disk", default) or `agg_logical` / `logical` ("Claimed"); hard-link duplicates weigh 0 (their `allocated` is already 0); dataless nodes weigh 0 under "On disk" and are drawn dashed with the caption "in the cloud" under "Claimed"; totals never include dataless bytes (spec §5, §17.1).
- Only official removal routes: a map path is trashed through `plan_paths` → the existing executor; a path inside a finding whose removal is not `Removal::Trash` (dev caches, models, apps, mise versions) is refused with a pointer to its category; scan roots, dataless nodes and protected locations are refused (spec §7, §17.3/5).
- The map never mutates the index. After a removal from the map the trashed subtrees are excluded from the layout until the next scan (the index is only rebuilt by a scan).
- No MCP changes: no new tool, parameter or output field. `PlanItem.parts` is `Option<u64>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`; `Engine::inspect`'s `owner_app` value may improve, its schema does not change. Snapshot format stays **3**.
- The map is one `canvas` per spec §10: no element or hitbox per tile; hover is a hit-test over the cached tile list; layout is recomputed only when root, depth, weight mode, exclusions or canvas size change, never on hover.
- Theme colours only (`cx.theme()`), English copy, sidebar/inspector widths unchanged (212 / 400 px).
- Owner rules (unchanged): automated runs never steal focus; `cargo test` opens no window and never touches real data; no full-screen screenshots; at most one short manual app launch per GUI task, quit by the implementer; no synthetic clicks/keys; tests never run `brew`/`pkgutil --forget`/`launchctl bootout`/`defaults delete`/`mise uninstall`; fixtures contain no real owner paths.
- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` green after every task; commit after each task. discky-app tests stay plain `#[test]` logic tests (no gpui test harness); do not `use super::*` in test modules (the GPUI glob shadows `test`).

## Review Focus

1. **A tile inside a command-managed finding** (a crate inside `~/.cargo/registry`, a blob inside `~/.ollama/models`, a folder inside an `.app`): "Move to Trash" must be refused with "Managed by Dev caches; remove it from there", not trash a piece of something an official command owns. → Task 3 (`refuses_paths_inside_command_managed_findings`).
2. **Protected and root paths** (`~/Library` itself, `~/Library/Keychains/*`, `~/Library/Mobile Documents/*`, a scan root such as `~`): refused with a reason, never planned. → Task 3 (`refuses_roots_and_protected_locations`).
3. **Dataless and hard-link duplicates** must not inflate tiles: under "On disk" they vanish and the totals line ignores them; under "Claimed" dataless tiles appear dashed with "in the cloud". → Task 5 (`dataless_hidden_on_disk_dashed_when_claimed`).
4. **Thousands of tiny siblings** (`node_modules`): the layout caps children per node and tiles in total, merges the tail into one "N more" tile with the tail's full area, and hover/paint stay bounded. → Task 4 (`tail_is_merged_into_rest_preserving_area`), Task 5 (`layout_never_exceeds_max_tiles`).
5. **Snapshot replaced while the map is open** (rescan, reload from disk): the current folder is kept when its path still exists, otherwise the map returns to the top; session exclusions are cleared; a stale hover index never panics. → Task 5 (`set_snapshot_keeps_path_or_resets`, `tile_at_with_stale_index_is_none`).
